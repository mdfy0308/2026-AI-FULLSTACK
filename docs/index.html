    Spring BootMyBatisSpring SecurityReact

    서버와 화면을 분리하고, 팀원마다 맡을 도메인의 경계를 그었습니다. 권한 체계를 도입해 사원과 관리자가 볼 수 있는 범위를 갈랐습니다. 다만 조회 조건이 늘어날수록 쿼리가 길어지는 문제가 남았습니다.

    3차 화면 16:9

    운영을 염두에 둔 재설계

    Spring Boot 4JPA + MyBatisRedisNext.jsOpenAI API

    기존 테이블은 손대지 않고 MyBatis에 그대로 둔 채, 평가·연차처럼 새로 만든 영역만 JPA로 옮겼습니다. 두 방식이 섞이면 추적이 어려워지므로 서로를 엔티티로 엮지 않고 참조 컬럼만 들고 있도록 경계를 그었습니다.

    인사평가 리포트 생성이나 안내 메일처럼 외부로 나가는 작업은 트랜잭션이 끝난 뒤에 실행되도록 미뤘습니다. 뒤늦게 롤백됐을 때 이미 발송된 메일은 되돌릴 수 없기 때문입니다.

    여기에 사내 인사 규정을 근거로 답하는 챗봇을 붙였습니다. 한국어 문서에서는 고정된 유사도 기준이 잘 맞지 않아, 가장 관련 있는 문단을 기준으로 삼는 상대적인 방식으로 바꿔 엉뚱한 답변을 줄였습니다.

    기능이 도는 것과 운영에서 버티는 것은 다르다는 감각을 얻은 단계.
