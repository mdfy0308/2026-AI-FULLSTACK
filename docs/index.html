PROJECT

SBerp · Spring Breeze ERP — 사내 인사·근태 관리 시스템

어떤 서비스인가

중소기업의 흩어진 업무 데이터를 한 곳에 모으는 사내 ERP입니다.
회사·부서·사원 같은 조직 정보를 축으로 인사, 근태, 전자결재, 프로젝트, 자원 예약이 서로 연결됩니다. 모든 데이터는 회사 단위로 분리되어, 여러 회사가 같은 시스템을 나눠 쓸 수 있습니다.

저는 사원 관리·근태·직급·인사 평가 영역을 맡았습니다.
사원과 직급, 권한, 출퇴근 집계와 연차 정산, 인사평가와 AI 리포트 기능을 구상하고 여기에 인사 규정을 답해주는 챗봇과 관리자 대시보드를 더했습니다.

    화면은 JSP가 서버에서 직접 그렸고 인증은 세션으로 처리했습니다. 한 파일 안에 화면과 로직이 합쳐져 있어서, 병합할 때 모듈 사이의 충돌을 미리 알아채기 어려웠습니다.

    2차 화면 16:9

    프레임워크 전환과 외부 연동

    Spring Boot 3Java 17ThymeleafOracle 18cSpring SecurityOpenAI

    2026.07 · 14일 · 4인 1차 프로젝트를 Spring Boot로 옮기고 DB도 Oracle로 바꿨습니다. 인증은 Spring Security로 대체했습니다. 인원이 여섯에서 넷으로 줄어 한 사람이 맡는 도메인이 넓어졌고, 저는 인사에 더해 평가와 권한을 함께 맡았습니다.

    그리고 처음으로 외부 서비스를 연동했습니다. 사원 등록 즉시 온보딩 메일이 자동으로 나가도록 만들었고, 평가 마감 시점에 코멘트를 AI가 요약하도록 했습니다. 외부 호출은 실패할 수 있으므로 평가 진행 상태를 여섯 단계로 쪼개 실패를 따로 관리했습니다.

    기능을 설계할 때는 실패 상황을 함께 고려해야하며, 보안의 중요성을 배우기 시작한 단계.

    3차 화면 16:9

    서버와 화면의 완전 분리

    Spring Boot 4JPA + MyBatisJWTRedisNext.jsRedux-SagaOpenAI

    2026.08 · 4인 가장 크게 바뀐 부분은 구조입니다. 서버는 REST API만 제공하고, 화면은 Next.js가 따로 맡습니다.
    세션 대신 JWT를 이용하며 발급된 토큰은 Redis에서 관리해 로그아웃과 만료를 서버가 제어할 수 있게 했습니다.

    고도화를 진행하며 추가로 근태와 연차 정산, 관리자 대시보드 기능을 추가했습니다. 기존 테이블은 MyBatis를 그대로 이용하되, 근태·연차·평가처럼 새로이 추가한 영역은 JPA로 작성했으며 서로를 엔티티로 엮지 않고 참조 컬럼만 가지고 가도록 경계를 두었습니다.
    이때 사내 인사 규정을 근거로 답하는 챗봇 기능을 함께 개발했는데, 한국어로 작성된 문서에서는 고정된 유사도 기준이 잘 맞지 않아 답변을 찾지 못하는 문제가 발생했었습니다. 이것을 가장 관련 있는 문단을 기준으로 삼는 상대적인 방식으로 바꿔 문제를 해결했습니다.

    기능이 도는 것과 운영에서 버티는 것은 다르다는 감각을 얻은 단계.
