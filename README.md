## 5. 트러블슈팅

### 사례 1. readOnly 트랜잭션 + self-invocation → 데이터 유실

**문제**
- `@Transactional(readOnly=true)` 클래스에서 쓰기 메서드를 내부 호출 → JPA가 flush를 하지 않아 INSERT/UPDATE가 통째로 유실. API는 성공(`count: 87`) 응답하면서 실제 저장은 0건.

**원인**
- `self-invocation`은 프록시를 거치지 않으므로, 내부 호출된 메서드의 `@Transactional` 설정이 무시됨

**해결**
- 내부 코어를 `private`으로 분리, `calculateAllForYear()`에 명시적 `@Transactional` 적용. 프록시를 안 거친다는 사실이 코드 수준에서 드러나도록 설계

**학습**
- **예외가 나지 않는 결함**이 가장 위험하다 — "테스트 통과 ≠ 올바름"

### 사례 2. 박싱된 Long 참조 비교 (ID > 127 → 403 에러)

**문제**
- `Long != Long`이 값이 아닌 참조를 비교. `-128~127` 캐시 범위 안에서만 동작하고, 사원 ID가 128을 넘는 운영 환경에서 본인 리포트에도 403 반환

**원인**
- Java의 `Long` 오토박싱 캐시 범위(`-128~127`) 밖에서는 `!=`가 참조(주소) 비교로 동작

**해결**
- `Objects.equals()`로 전면 교체

**학습**
- 개발 DB에서 재현되지 않는 유형 — 데이터 규모에 따라 달라지는 조건을 항상 고려할 것

### 사례 3. RAG 유사도 임계값 — 한국어 임베딩 특성 대응

**문제**
- 절대 임계값(`SIMILARITY_THRESHOLD=0.3`)으로는 한국어 임베딩의 전반적 낮은 유사도 때문에 핵심 조항(0.246)이 탈락

**원인**
- 한국어 텍스트는 영어 대비 임베딩 벡터 간 코사인 유사도가 전반적으로 낮게 형성

**해결**
- **상대적 필터링** 전환 — 1위 대비 50% 이상인 청크만 포함. 음수 엣지케이스도 별도 처리

**학습**
- 절대값 기반 필터링의 한계를 인식하고, 데이터 특성에 따른 상대적 기준 설계의 중요성

### 사례 4. 멀티테넌시 보안 구멍 (타사 사원 데이터 접근)

**문제**
- A사 관리자가 B사 사원의 empId만 알면 조회·수정·차감 가능. 8개 엔드포인트에서 `comId` 검증 누락

**원인**
- 도메인 개발 시 회사 간 격리(테넌시 가드)를 고려하지 않고 기능 중심으로만 구현

**해결**
- `existsByEmpIdAndCompany_ComId()` 파생 쿼리 + `assertSameCompany()` 가드 메서드. Employee → Company 연쇄 로딩 시 `@Lob` 충돌을 FK 직접 비교로 회피

**학습**
- 보안은 기능 완성 후 추가하는 것이 아니라 설계 단계에서 함께 고려해야 함

### 사례 5. Git 6인 협업 충돌 (1차 → 3차 진화)

**문제**
- 1차 프로젝트에서 6명이 병렬 개발 후 1차 병합 시 대규모 충돌 발생

**원인**
- Git 브랜치 전략 미수립 + 팀원 다수가 Git 협업 워크플로우에 익숙하지 않은 상태

**해결**
- 별도 병합·보완 구간 운영 → 2·3차에서 브랜치 전략 정립. 3차에서는 도메인 경계를 엄격히 나누고, 팀원 파일을 건드리지 않는 **오버로드 확장** 패턴 적용

**학습**
- 신규 개발자가 포함된 팀일수록 Git 전략을 프로젝트 초반에 합의해야 병합 리스크를 줄일 수 있음

## 7. 자체 평가

### 잘한 점

- 3세대에 걸쳐 같은 시스템을 반복 고도화하며 **리팩토링의 실제 비용과 효과**를 체험
- 코드 리뷰 피드백을 지적된 파일에만 적용하지 않고, **같은 기준으로 전체를 스캔**하는 습관
- RAG 파이프라인 · 대시보드 · 근태/연차 등 **도메인 간 연동**이 필요한 기능을 직접 설계·구현
- 팀원 도메인 경계를 존중하면서 시그니처를 확장하는 **오버로드 패턴** 적용

### 아쉬운 점

- 통합 테스트 케이스 부족 — 대량 데이터 기준 페이징 테스트 미진행
- 프론트엔드 권한 가드를 백엔드보다 늦게 적용 (사용자가 403을 맞는 구간 존재)
- RAG에서 VectorDB 미사용 — Java 코사인 유사도 직접 계산으로 대규모 문서에는 한계

### 배운 점

- `@Transactional(readOnly=true)` + self-invocation처럼 **예외가 나지 않는 결함**이 가장 위험하다
- 개발 환경에서 재현되지 않는 조건(Long 캐시 범위, 데이터 규모)을 항상 고려해야 한다
- 리뷰는 "이 파일을 고쳐라"가 아니라 **"이 기준으로 전체를 보라"**로 읽는 것
